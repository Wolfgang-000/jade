
# C端营销活动网站 → 微信小程序完整版

这不是把原来的 HTML 简单塞进 `web-view`，而是按微信小程序重新拆成原生页面。

## 最重要的架构决定

**消费者前台改成微信小程序；运营 CMS 继续保留 Web 后台。**

原因：运营人员需要商品表格、批量导入、活动编辑、数据中心、合规审核和大量表单，桌面 Web 后台效率明显高于在小程序里管理。

结构：

`Web CMS 后台 → API/数据库 → 微信小程序 → 现有C端商城`

小程序只负责：活动展示、会员权益、商品导流、渠道追踪。

## 立即预览

1. 安装“微信开发者工具”。
2. 导入本目录作为项目。
3. `project.config.json` 当前使用 `touristappid`，可以先预览UI。
4. 正式接入时把 AppID 换成你公司申请的小程序 AppID。
5. 修改 `miniprogram/config/index.js` 中的商城 AppID、商城路径和 API 地址。

## 商城跳转两种模式

### A. 已有商城也是小程序（推荐）
`MALL_MODE: 'miniProgram'`

“立即购买”调用 `wx.navigateToMiniProgram`，跳转到已有商城商品页。

### B. 已有商城是 H5
`MALL_MODE: 'webview'`

通过 `<web-view>` 打开 H5 商城。正式使用前必须按微信要求配置业务域名/合法域名。

## 生产版需要后端提供的接口

- `GET /api/public/home`
- `GET /api/public/activities`
- `GET /api/public/activities/:id`
- `POST /api/track/events`

CMS 发布后，小程序从 API 读活动数据，因此运营换 Banner、商品、活动价、链接时，不需要重新发布小程序代码。

## 合规策略

“广告审核”不建议继续只用一个模糊字段。生产版应拆成：

- 商品属性
- 是否允许公众推广
- 法定广告审查状态/批准信息
- 有效期
- 内部合规复核
- 当前活动发布资格

运营只看到最终结果：**可以发布 / 暂不可发布**，并能展开查看原因。
