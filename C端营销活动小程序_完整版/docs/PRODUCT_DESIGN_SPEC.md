# 澄和健康 · 医药健康商城微信小程序产品与设计规范

## 1. 产品定位
定位：高端零售体验驱动的专业医药健康商城。
价值公式：医药专业可信度 × 高端零售体验 × 电商转化效率 × 会员运营能力。
核心用户：普通消费者、家庭健康管理用户、慢病管理用户、会员用户、健康产品购买用户。
核心经营：OTC、医疗器械、健康用品、营养健康、个人护理、家庭常备、季节健康、品牌专区、会员商品、健康内容。

## 2. 用户画像
- 家庭健康管理者：需要可靠、清晰、快速完成家庭常备采购。
- 会员复购用户：关心复购效率、会员价、积分、优惠和订单服务。
- 慢病管理用户：更关注持续服务、专业信息、监测设备和药师支持。
- 健康消费用户：关注营养、护理、生活方式与品牌质感。
- 受监管购药用户：需要明确的身份、处方、药师与审核流程。

## 3. 用户旅程
购物：微信入口 → 首页/搜索/分类/活动 → 商品详情 → 规格 → 购物袋/立即购买 → 登录/地址 → 优惠 → 订单确认 → 支付 → 订单 → 物流 → 收货 → 售后 → 复购。
会员：首页 → 会员中心 → 权益 → 会员商品/活动 → 购买 → 积分 → 等级成长 → 再消费。
健康服务：首页/健康 → 场景/内容 → 商品 → 专业信息 → 药师咨询 → 合规购买流程。

## 4. 信息架构
一级Tab： 首页 / 分类 / 健康 / 购物袋 / 我的。
二级：搜索、品牌馆、活动中心、会员中心、订单中心、药师咨询、客服、收藏、优惠券、积分、地址、设置。
三级：商品详情、规格选择、订单详情、物流、说明书、售后、隐私/协议。

## 6. 首页结构
品牌头部 → 搜索 → Hero Campaign → 横向高频分类 → 会员权益 → Editorial精选 → 更多精选 → 健康场景 → 品牌专区 → 健康内容。
原则：不做九宫格；不做满屏促销；不无限滚动堆SKU；让场景和品牌承担导航。

## 7. 商品详情
视觉区：大图轮播 / 视频扩展位 / 收藏 / 分享。
核心信息：名称、通用名、规格、品牌、厂家、属性、价格、会员价、库存、配送。
专业信息：批准/注册、储存、效期说明、产品说明/说明书入口。
服务：客服、药师咨询、正品/隐私/售后说明。
购买：普通商品加入购物袋/立即购买；受监管商品切换为咨询/处方/审核流程。

## 8. 购物流程
购物袋负责选择与数量；结算页统一计算优惠与资格；提交订单前服务端必须重新校验库存、价格、优惠、配送、限制、身份与处方要求；支付金额不得由前端单独决定。

## 9. 会员体系
等级示例：普通 / 银卡 / 金卡 / 黑金。
核心权益：会员价、积分、生日礼遇、专属活动、新品优先、会员客服、健康服务。
会员中心使用品牌化会员卡，不使用传统“图标菜单墙”。

## 10. 医药业务特殊流程
商品监管模式建议统一为：
- general：普通健康商品
- wellness：营养健康
- device：医疗器械
- otc：OTC
- rx：处方/受监管流程
受监管商品必须由后端规则决定CTA、身份校验、药师审核、处方流转、配送与售后能力；前端不得把普通购物链路硬套到所有商品。

## 11. UI Design System
风格：Premium pharmaceutical retail / Editorial commerce / Sophisticated minimalism。
核心：暖白中性底、深灰文字、低饱和品牌强调色、极弱边框、少阴影、摄影优先、强Typography、克制促销。
禁止：大红、传统药房蓝绿模板、玻璃拟态、廉价渐变、卡片泛滥、强阴影、满屏标签。

页面左右主要边距：32rpx。

## 15. Component System
Button：Primary / Secondary / Text / Danger。
Tag：中性 / 品牌 / Success / Warning / Danger。
Product Card：首页视觉型；搜索/分类信息型。
List Row：订单、菜单、地址、筛选。
Member Panel：会员等级/积分/权益。
Editorial Module：主推大图 + 次级内容。
Timeline：物流。
Chat：药师咨询。
Notice：监管/风险信息。
Skeleton / Empty / Error：异常状态。

## 16. 页面交互
- 首页搜索、横滑分类、Hero跳活动、精选跳商品。
- 商品规格选择、数量控制、收藏、加入购物袋。
- 购物袋数量、删除、选中、结算。
- 结算提交前校验。
- 订单查看、物流、再次购买、售后。
- 药师咨询独立于普通客服。
- 分享：商品/活动预留 shareAppMessage/shareTimeline。
- 小程序码、订阅消息、微信支付、微信地址在生产接入层实现。

## 18. 响应式
微信小程序以375/390宽为主。
小屏优先重排而非等比缩放：
- 双列商品在极窄设备保持可读性；
- 复杂表格改列表；
- 底部CTA固定在安全区；
- 横向分类允许滚动；
- 文本溢出限制2–3行；
- 避免依赖Hover。

## 19. 小程序实现建议
前端：原生微信小程序或TDesign/自建Design System；本原型使用原生组件。
后端：活动/商品/会员/订单/优惠/合规/内容/API分域。
状态：服务端为订单、库存、价格、资格最终真源。
微信能力：微信登录、微信支付、地址、分享、朋友圈、小程序码、订阅消息。
数据：埋点至少覆盖曝光、搜索、商品点击、加购、结算、支付、订单、复购、会员权益和药师服务。

## 20. 商业落地原则
1. 前台不承担法规判断，后端规则引擎返回“可展示/可购买/CTA模式/风险提示”。
2. 运营后台管理商品营销字段、活动模块、品牌内容、健康内容与合规状态。
3. 商品主数据、库存、价格、订单、资格校验应由正式业务系统/API提供。
4. 图片需替换为品牌自有或已获授权的高质量商业素材。
5. 原型中的商品、批准信息、链接和部分医疗内容均为演示数据，不可直接作为真实经营信息发布。
